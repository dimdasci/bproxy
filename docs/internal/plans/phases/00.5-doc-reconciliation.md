**Goal:** Propagate PoC verdicts into the design docs so Phase 1 builds on validated reality, not stale assumptions. Two PoC verdicts require propagation: PoC 2 (pairing transport, ⚠️ modifies) and PoC 3 (write technique, ⚠️ modifies). PoC 1 confirmed the design — no changes.

**Strategy:** Decisions first, then top-down. Rethink at the ADR and architecture level, then propagate downward into solution specs. The journal (`docs/journal/`) preserves historical deliberation; `docs/decisions.md` becomes a clean current-state edition.

**Spec:** [`docs/plans/roadmap.md`](../roadmap.md) — Phase 0.5 section. Done when every PoC verdict that modifies or invalidates a design choice has produced corresponding edits in architecture + decisions + solution specs, committed.

## Locked outcomes for this phase (open questions closed)

1. **Pairing transport is popup-driven claim only.** No CLI→extension runtime bridge, no `onMessageExternal` bootstrap path.
2. **`POST /pair/claim` uses pairing code as auth factor.** No daemon bearer token required on popup claim route.
3. **Write protocol is explicit, no `auto`.** `fill.method` is one of: `direct` | `paste` | `runtime-api`.
4. **No extension-side escalation/classification/cache.** Agent selects selector/route, method, and world per call.
5. **`runtime-api` writes require MAIN world (on-demand one-shot).** `direct` and `paste` stay ISOLATED.
6. **Shadow-DOM-aware targeting is part of the contract.** Shared types must support element routes beyond plain light-DOM selectors.
7. **MAIN-world hygiene is mandatory.** Catch errors in injected functions; do not leak `chrome-extension://` stack URLs.
8. **`web_accessible_resources` is default-deny.** Carve-outs are explicit ADR-governed exceptions.
9. **Polling is jittered and visibility-aware.** No fixed cadence loops; destructive actions bail on hidden tabs unless explicitly user-initiated.
10. **Agent method-selection guidance lives outside extension code** (skill/spec document), not as hidden extension heuristics.
